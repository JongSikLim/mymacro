# MyMacro

Windows용 간단한 매크로 도구. 마우스/키보드 입력, 딜레이, 이미지 인식 조건부 입력, 반복과 분기를 지원합니다.

## 설치와 실행

Python 3.10 이상이 필요합니다. ([python.org](https://www.python.org/downloads/windows/) 설치 시 "Add python.exe to PATH" 체크)

```
setup.bat      한 번만: 가상환경 생성 + 의존성 설치
start.bat      실행
check_input.bat  입력이 다른 프로그램에 전달되는지 자동 검사
test.bat       단위 테스트
build.bat      dist\MyMacro.exe 생성
```

## 단축키

| 키 | 동작 |
|----|------|
| F8 | 녹화 시작 / 중지 |
| F9 | 매크로 실행 |
| F10 | 중지 |
| 마우스를 화면 왼쪽 위 모서리로 | 비상 정지 |

F8/F9/F10은 다른 프로그램을 쓰는 중에도 동작합니다.

주의: 매크로 안에서 F8/F9/F10을 입력하면 매크로가 자기 자신을 제어하게 됩니다. 대상 프로그램에서 그 키가 필요하면 매크로를 다시 설계하세요.

## 기능

### 1. 마우스 / 키보드 입력

**녹화**: F8을 누르고 평소처럼 조작한 뒤 다시 F8을 누릅니다. 클릭, 드래그, 스크롤, 키 입력, 단축키 조합이 좌표와 함께 단계 목록으로 들어갑니다. 동작 사이의 시간 간격도 딜레이 단계로 같이 기록되므로, 나중에 "4초 대기"를 "200ms 대기"로 줄일 수 있습니다.

**직접 추가**: 오른쪽 버튼으로 단계를 하나씩 추가합니다. 좌표는 `화면에서 찍기 (F2)` 버튼을 쓰면 됩니다. 창이 가려지지 않으니 다른 프로그램의 버튼 위에 마우스를 올려두고 F2만 누르면 그 좌표가 들어갑니다.

지원하는 마우스 동작: 좌/우/휠 클릭, 더블클릭, 이동, 드래그, 스크롤, 버튼 누르고 있기/떼기
지원하는 키 동작: 키 입력, 단축키 조합, 텍스트 입력, 키 누르고 있기/떼기

한글과 이모지도 텍스트 입력으로 바로 들어갑니다.

### 2. 딜레이

고정 시간 대기. `무작위 폭`을 주면 매번 ±그만큼 흔들립니다. 간격이 기계처럼 일정한 것을 피하고 싶을 때 씁니다.

### 3. 이미지 인식 조건부 입력

`이미지 조건 추가` → `화면에서 캡처`로 찾을 그림을 드래그해서 잘라냅니다. 화면이 멈춘 상태로 캡처하므로 정확히 원하는 영역을 집을 수 있습니다.

그 다음 두 갈래로 단계를 넣습니다.

```
이미지 조건: login_button.png (정확도 0.85, 최대 5000ms 대기)
  └ 찾았을 때
      좌클릭 (찾은 위치)
      1000ms 대기
  └ 못 찾았을 때
      키 입력 esc
```

- **정확도**: 0.80~0.90이 보통 잘 맞습니다. 못 찾으면 낮추세요.
- **검색 범위**: 영역을 지정하면 그 안에서만 찾습니다. 훨씬 빠르고 오탐이 줄어듭니다.
- **최대 대기**: 0이면 즉시 한 번만 확인합니다. 값을 주면 나타날 때까지 기다립니다. 로딩을 기다릴 때 씁니다.
- **찾으면 그 위치를 클릭**: 버튼 위치가 매번 달라져도 따라갑니다.
- **지금 화면에서 찾아보기**: 매크로를 돌리기 전에 인식이 되는지 바로 확인합니다.
- **마지막으로 찾은 자리를 먼저 확인**: 기본으로 켜져 있습니다. 아래 성능 항목을 보세요.

#### 성능: 위치 캐시

이미지 찾기는 매번 화면을 캡처하고 전체를 훑는 연산입니다. 1512x982 화면에서 한 번에 **약 30ms**, 2560x1440이면 100ms쯤 듭니다. 반복 안에 넣으면 이 비용이 그대로 쌓입니다.

그래서 **직전에 찾은 위치 주변(템플릿 + 상하좌우 30px)을 먼저** 봅니다. 거기 있으면 끝이고, 없으면 평소대로 전체를 다시 찾습니다. 픽셀은 어느 쪽이든 실제로 확인하므로 **결과는 달라지지 않고 속도만 바뀝니다.**

같은 화면에서 실측한 값입니다.

| | 시간 |
|---|------|
| 캐시 없음 (전체 화면) | 30.4 ms |
| 캐시 적중 | **4.2 ms** (7.1배) |
| 캐시 빗나감 -> 전체 탐색 폴백 | 35.0 ms (+4.6 ms) |

100회 반복하는 루프라면 탐색에만 쓰는 시간이 3.0초에서 0.42초로 줄어듭니다. 빗나갈 때 손해는 15%뿐이라, 켜두는 쪽이 거의 항상 이득입니다.

캐시가 하는 일과 하지 않는 일:

- 창이 조금 움직여도 30px 안이면 그대로 적중합니다.
- 창이 크게 움직이거나 해상도가 바뀌면 빗나가고, 전체 탐색으로 **스스로 복구**한 뒤 새 위치를 기억합니다.
- 이미지를 못 찾으면 기억을 지웁니다. 사라진 대상을 계속 그 자리에서 찾지 않습니다.
- 단계마다 따로 기억하고, 실행을 시작할 때마다 비웁니다. 이전 실행의 화면을 믿지 않습니다.
- `이미지가 나타날 때까지` 반복에는 효과가 없습니다. 기억해둘 이전 위치가 없기 때문입니다.

실행 로그에 `[캐시]` / `[전체 탐색]` 이 찍히고, 끝나면 적중/빗나감 횟수가 나옵니다.

검색 범위를 직접 지정하면 캐시와 비슷한 효과를 얻습니다. 어디 나올지 이미 안다면 그쪽이 더 확실합니다. 둘을 같이 써도 됩니다.

### 4. 흐름 제어

전체 반복(위쪽 `전체 반복` 칸)과 별개로, **일부 단계만 반복**하거나 **앞으로 되돌아갈** 수 있습니다.

**반복 블록**: 안에 넣은 단계만 반복합니다. 네 가지 방식이 있습니다.

| 방식 | 언제 쓰나 |
|------|-----------|
| 정해진 횟수만큼 | 10번 클릭 같은 단순 반복 |
| 무한 | 조건이 맞을 때까지 계속. `루프 탈출`로 빠져나갑니다 |
| 이미지가 보이는 동안 | 로딩 표시가 사라질 때까지 계속 |
| 이미지가 나타날 때까지 | 버튼이 뜰 때까지 계속 |

무한/이미지 방식에는 `최대 반복` 안전장치가 있습니다. 조건이 끝내 안 바뀌어도 그 횟수에서 멈춥니다.

**라벨**과 **흐름 제어**로 되돌아갑니다.

| 단계 | 동작 |
|------|------|
| 라벨 | 돌아올 위치에 이름을 붙입니다. 맨 바깥 목록에만 둘 수 있습니다 |
| 루프 탈출 | 가장 가까운 반복 블록을 빠져나옵니다 |
| 다음 반복으로 | 이번 회차의 남은 단계를 건너뜁니다 |
| 매크로 처음으로 | 첫 단계부터 다시 시작합니다 |
| 라벨로 이동 | 지정한 라벨로 돌아갑니다 |
| 매크로 종료 | 전체 반복까지 즉시 끝냅니다 |

블록은 5단계까지 겹칠 수 있습니다. 반복 블록 안에 이미지 조건을 넣고, 그 안에 또 반복 블록을 넣는 식입니다.

#### 예: 선행 작업 후 조건부 루프, 조건이 맞으면 처음으로

```
1. 라벨: 시작
2. 좌클릭 (120, 340)        ← 선행 작업
3. 키 입력 enter
4. 500ms 대기
5. 반복 (무한, 최대 100회)
   └ 반복할 내용
       1. 좌클릭 (400, 500)        ← 반복할 작업
       2. 이미지 조건: done.png
          └ 찾았을 때
              1. 루프 탈출          ← 끝났으면 루프 밖으로
       3. 이미지 조건: error.png
          └ 찾았을 때
              1. 라벨 '시작' 로 이동  ← 오류면 처음부터 다시
6. 좌클릭 (800, 900)        ← 루프를 빠져나온 뒤 마무리
```

`error.png`가 보이면 5번 루프를 빠져나와 1번 라벨로 돌아가 선행 작업부터 다시 합니다. `done.png`가 보이면 루프만 탈출해 6번으로 넘어갑니다.

제자리에서 도는 무한 루프는 자동으로 막습니다. 되돌아가는 사이에 실행되는 단계가 하나도 없으면 매크로를 멈추고 로그에 이유를 남깁니다.

## 다른 프로그램에 입력이 들어가는 원리

입력은 `SendInput`으로 **시스템 입력 큐**에 넣습니다. 특정 창을 지정해 보내는 것이 아니라 OS 입력 흐름에 끼워 넣는 방식이라, **그 순간 포커스를 가진 창**이 받습니다. MyMacro 창은 뒤에 있어도 되고, 실행 중에는 기본으로 최소화됩니다.

좌표는 `SetCursorPos`로 옮깁니다. 가상 데스크톱 전체 기준이라 두 번째 모니터나 음수 좌표에서도 정확합니다.

### 입력이 안 들어갈 때

`check_input.bat`을 실행하면 자동으로 원인을 좁혀줍니다. 빈 메모장을 띄워놓고 돌리면, 메모장에 글자를 넣고 Ctrl+A / Ctrl+C로 다시 읽어와서 **실제로 다른 프로그램에 전달됐는지**까지 확인합니다.

흔한 원인 세 가지입니다.

1. **대상이 관리자 권한으로 실행 중** — 가장 흔합니다. Windows UIPI 때문에, 권한이 낮은 프로그램이 보낸 입력은 오류 없이 조용히 버려집니다. MyMacro도 관리자 권한으로 실행하세요 (우클릭 → 관리자 권한으로 실행). 앱의 `도구 → 입력 진단`에서 현재 권한을 확인할 수 있습니다.
2. **DirectInput을 쓰는 게임** — 일부 게임은 주입된 입력을 무시합니다. 이건 우회할 수 없습니다.
3. **백신/보안 프로그램의 차단** — 매크로를 키로거로 판단해 막는 경우가 있습니다.

## 매크로 파일

`macros\*.json`으로 저장됩니다. 사람이 읽고 고칠 수 있는 형식입니다. 캡처한 이미지는 `macros\images\`에 들어갑니다. 매크로를 옮길 때는 두 폴더를 같이 옮기세요.

## 파일 구조

```
run.py                  진입점 (DPI 설정 후 앱 시작)
mymacro/
  models.py             매크로 자료구조 (단계, 블록, 라벨)와 JSON 저장/불러오기
  input_backend.py      SendInput 기반 입력 주입
  player.py             매크로 실행과 흐름 제어
  recorder.py           입력 녹화
  vision.py             화면 캡처와 이미지 찾기 (OpenCV), 위치 캐시
  keymap.py             키 이름 변환
  hotkeys.py            전역 단축키
  diagnostics.py        권한/DPI/모니터 진단
  platform_utils.py     DPI 인식 설정
  paths.py              매크로/이미지 폴더 위치
  ui/
    main_window.py      메인 창
    step_dialogs.py     단계 편집 창
    pickers.py          좌표 찍기, 영역 드래그 캡처
tools/check_input.py    입력 전달 자동 검사
tests/                  단위 테스트
```

## 기술 메모

입력 주입에 pyautogui를 쓰지 않습니다. pyautogui의 Windows 백엔드에는 이 도구에 치명적인 문제가 두 개 있습니다.

1. 클릭 좌표를 **주 모니터 기준**으로 정규화합니다 (`65536 * x // GetSystemMetrics(0)`). 두 번째 모니터의 클릭이 엉뚱한 곳에 떨어지고, 음수 좌표를 쓸 수 없습니다.
2. `keybd_event(vk, 0, ...)`로 스캔 코드를 0으로 보내고 `KEYEVENTF_EXTENDEDKEY`를 설정하지 않습니다. 방향키, Delete/Insert, Home/End, PageUp/PageDown, 오른쪽 Ctrl/Alt가 확장 비트 없이 전달됩니다.

대신 pynput의 컨트롤러를 씁니다. 녹화에 이미 쓰고 있던 라이브러리이고, `SendInput`을 사용하며 `MapVirtualKey`로 스캔 코드를 채우고 확장키 플래그를 올바르게 설정합니다. 유니코드는 `KEYEVENTF_UNICODE`로 직접 보내므로 한글 입력에 클립보드 우회가 필요 없습니다.

`platform_utils.bootstrap()`은 Qt보다 먼저 실행되어야 합니다. 프로세스를 per-monitor DPI aware로 만들고 Qt 자체 스케일링을 끄기 때문에, pynput이 읽는 좌표 / mss가 캡처하는 픽셀 / Qt가 그리는 위치가 모두 같은 물리 픽셀이 됩니다.

## 검증 상태

- 단위 테스트 66개 통과 (`test.bat`). 자료구조 왕복, 녹화→재생 경로, 조건 분기, 반복/라벨/점프, 무한 루프 차단, 중지 동작을 가짜 입력 백엔드로 검사합니다. 위치 캐시는 합성 화면으로 적중/빗나감/경계 클램핑까지 확인하고, UI는 오프스크린으로 조립해 트리 구성과 모든 편집 창을 확인합니다.
- 키 이름 테이블은 pynput의 **Windows** 키 목록과 대조해 검증했습니다.
- 실제 Windows에서의 입력 전달은 `check_input.bat`으로 확인하세요. 작성 환경이 macOS라 아직 실기 검증은 되지 않았습니다.
